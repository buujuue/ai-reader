# 02 — 让 Markdown 复用全局主题并保持编辑恢复一致

状态：已按用户确认发布为 [GitHub #72](https://github.com/buujuue/ai-reader/issues/72)，标签 `ready-for-agent`。原生依赖：受 #71 阻塞；只有阻塞事项完成后才能进入执行前沿。

## 要交付的行为

Markdown 阅读视图复用可重排 EPUB 已建立的五主题配色能力。用户切换全局主题后，Markdown 页面基础背景和普通正文立即与主题一致；在源码模式编辑、正式保存、恢复快照或切回阅读模式后，仍显示最新文本及当前全局主题。同一材料跨两个 Editor Group 打开时，共享内容会话和全局配色，保留各自阅读位置。

## 验收标准

- [ ] Markdown 使用已有五主题入口与同一配色来源，不新建 Markdown 专属主题、映射副本或存储通道；科技黑普通文字为 #ffffff，其余四主题为 #000000，页面基础背景采用当前全局主题的不透明纸张色。
- [ ] 从全局和书籍设置调整或重置阅读排版时，适用 EPUB／Markdown 均不会暴露旧三主题选择，也不会被遗留 theme 值覆盖；摘要显示实际全局主题。字体、字号、行距、页边距等其它偏好继续按既有作用域生效；排除格式的原有行为不受影响。
- [ ] 阅读模式的默认正文与明确纯黑文字使用前置工单的 Readest 兼容规则，显式灰色不另加强制覆盖；经现有安全解析后保留的彩色内容、彩色继承后代、链接、代码、局部背景、图片、SVG/公式以及高亮/搜索/选区保持既有颜色与语义，不放宽内容清洗来增加自定义样式能力。
- [ ] 切换全局主题不改动 Markdown 源文本、共享会话脏状态、撤销历史、正式版本或恢复快照；源码编辑器保留原有语法高亮和选区语义，不给源码文本套用书内文字替换逻辑。
- [ ] 在源码模式切换主题后，返回阅读模式必须使用最新主题和当前共享缓冲区；未保存编辑、正式保存、放弃编辑、载入恢复快照及启动恢复后的阅读重建，均不能恢复旧主题或过期文本。
- [ ] 同一材料在两个 Editor Group 中分别处于阅读和源码模式时，阅读侧显示最新会话内容和全局主题；两个阅读视图也一致跟随。位置、模式、选区归属和编辑焦点仍各自独立，源码编辑区与 Foliate 不同时占有同一可见区域。
- [ ] Markdown 的分页/滚动、跨章节、挂起回切、缓存淘汰冷重建和打开途中主题切换均在展示前采用最新配色；EPUB→Markdown→PDF→EPUB 的混合轮换不产生旧主题闪回，不改变三 resident／两 active 资源边界，也不使 PDF 跟随全局正文配色。
- [ ] 重启和整库恢复后使用当前本机主题，既有 Markdown 内容、批注和全局/材料非颜色排版可恢复；不把有效全局主题写入材料或书库备份。
- [ ] 同步 Markdown 领域说明、主题迁移范围、架构与受影响 CODEMAP，明确依赖既有全局配色能力；直接移植 Readest 代码时补齐来源和许可登记。
- [ ] 使用真实 Markdown 阅读文档验证五主题与颜色保真；应用 Seam 覆盖共享编辑会话、模式切换、正式保存、恢复快照、双组和三格式轮换，断言当前内容、配色、位置及锚点一致。相关测试、类型检查与生产构建通过，并补充 Windows Tauri 编辑后重启恢复与主题一致的冒烟证据。
