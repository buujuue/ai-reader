# 跨端验证约束

## 主工作流

仓库工作流 `/.github/workflows/cross-platform.yml` 监听以下事件：

- 每次推送到 `main`；
- Pull Request；
- 手动触发。

每次 `main` 推送都会在同一轮工作流中并行执行 Windows 和 macOS 验证。两端都运行 TypeScript 类型检查、前端测试、Rust 测试、Clippy 和前端构建；Windows 生成 NSIS 安装包，macOS 生成 `.app` 与 `.dmg` 构建产物。工作流不会取消同一分支上较早的运行，因此每次推送都有对应的验证结果。

“同步”指同一条工作流必须等所有矩阵任务完成后才得出最终结果；矩阵任务可以并行执行，但任一端失败都会使本次验证失败。

## 后续平台

后续加入 iPadOS、Android 或其他端的验证时，必须扩展这一工作流的矩阵，并继续使用 `push` 到 `main`、Pull Request 和手动触发这三类入口。单独运行某个平台、只做浏览器模拟，或只在本地验证，都不能替代主工作流中的跨端结果。

新增平台若需要专用工具链、签名或模拟器，应在同一工作流中新增对应 job，并明确把它纳入 `main` 推送的必跑路径；不要把它拆成只在手动触发时运行的旁路验证。
