# 完整备份包含书库文件夹结构

完整书库备份与恢复必须保留书库文件夹、父子关系、材料归属和树展开状态，并与现有书籍数据原子恢复。旧备份没有文件夹数据时，恢复后的材料统一进入未归类；这样不会丢失整理结果，代价是备份格式需要兼容一个新的文件夹数据版本。

## 决策

- 当前归档格式为 v2。`manifest.json` 的 `folders` 记录文件夹稳定 ID、名称和父级，`materials[].folderId` 记录材料唯一归属；完整 Workspace State（包括 `expandedLibraryFolderIds` 和 `unfiledMaterialsExpanded`）继续由同一 SQLite 一致快照保存，不在前端重复拼装。
- v2 恢复在 `stash` 暂存区校验 manifest 与 SQLite：文件夹 ID、名称、同级唯一性、父级引用、循环和五层深度必须有效；材料归属、SQLite 外键和 Workspace 树展开引用必须指向同一份文件夹集合。校验失败发生在当前书库安全快照和原子切换之前。
- v1 归档仍可读取。若旧数据库已经带有新表或新字段，恢复前在暂存数据库中清除文件夹、材料归属和树展开字段；若旧数据库没有这些结构，则由现有向前迁移创建空结构，因此全部材料进入未归类，书籍、封面、设置、位置、批注和标签仍保留。
- Rust 的 `db/backup.rs` 独立实现上述 tar/SQLite 归档协议；Readest 的 `backupService.ts` 只作为行为参考，没有直接复制其应用层代码。

## 后果

备份格式版本与数据库 schema 版本分离：格式 v2 能明确拒绝损坏的树关系，同时仍允许旧 v1 数据安全降级。代价是恢复旧归档需要一次暂存数据库规范化，且恢复成功后必须重新加载工作区，不能在当前运行时继续沿用旧的内存树。
