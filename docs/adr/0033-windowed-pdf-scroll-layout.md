# ADR-0033：PDF 滚动模式使用窗口化占位布局

## 状态

已接受（工单 #45）。

## 背景

旧的 `PdfRenderer` 为了计算滚动模式的总高度和每页偏移，挂载时依次调用全部页面的 `getPage()` 并读取真实 viewport。数百页 PDF 因此在首屏之前遍历全部页面对象，既延迟首个可见页面，也让解码页缓存和 Canvas 窗口化失去意义。

PDF 页面尺寸可能混合横竖页和不同纸张规格，但未知页面在取得 PDF.js 页面对象前不能读取真实 viewport。布局必须先有稳定的总高度，真实尺寸回来后还要避免改变前面页面高度导致当前阅读位置跳动。

## 决策

- 滚动模式先按 `595 × 842` CSS 像素为每页创建占位元素；占位只表达页数和暂估几何，不调用 `getPage()`。
- 使用以阅读容器为 root、预加载边距为 `200% 0` 的 `IntersectionObserver` 标记附近占位。调度器按当前页距离排序，最多同时读取/渲染 3 页；快速滚动时不为所有经过页面启动完整 Canvas、文字层和批注层。
- 已渲染页面最多保留 12 页。超出上限时只从不可见页中按距离从远到近释放；当前可见页不被驱逐。释放继续经过 `PdfPageRenderer.release()`，保持 Canvas 清零、渲染任务取消、文字层与批注覆盖层清理。
- 页面真实尺寸到达后更新该页自然尺寸，重算全部占位的 `top`/`height`，并以当前页码及页内滚动比例恢复 `scrollTop`。缩放、容器宽度变化、位置恢复和滚动竞态共用同一锚点路径。
- 分页模式仍只取得当前页并保留已有一页前瞻；PDF.js 范围读取上限、解码页 LRU、DPR/Canvas 像素上限、过期渲染取消和 `close` 释放边界不变。
- 当浏览器没有 `IntersectionObserver` 或首批异步回调尚未抵达时，使用同样的几何预加载窗口作为安全回退；这不改变页面占位和并发/内存上限。

## 取舍

未知页面的初始高度是估计值，第一次取得混合尺寸页面时总高度会渐进校正；页内比例锚点会保留用户看到的页面和相对位置，但不承诺从未加载页面的任意精确绝对 `scrollTop` 永远不变。把默认尺寸持久化或提前扫描全部页面都会重新引入首屏遍历，因此不在本工单范围内。

Readest 的 `packages/foliate-js/fixed-layout.js` 仅作为占位、IntersectionObserver、最近页面优先、并发上限、淘汰和锚点行为参考；AI Reader 保留自己的 `PdfRenderer`、`PdfPageRenderer`、`BookDocument` 和批注边界。
