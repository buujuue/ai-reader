# 使用稳定资料身份、完整指纹与托管导入

每份 Reading Material 使用稳定 UUID `BookId`。受管理导入的精确查重键由完整内容指纹与规范材料格式共同组成；完整内容指纹也用于完整性校验，但不是稳定身份。标题、作者和标识符等元数据不得触发自动合并。

所有导入文件复制到应用托管书库。导入采用 `stage → inspect → commit`：Rust 流式复制并计算指纹，TS 通过 BookDocument 检查格式和提取信息，Rust 再按「完整指纹 + 格式」查重，并以 IMMEDIATE 事务与 ready 唯一约束完成文件与数据库提交。启动时恢复会核对 pending 托管副本的指纹，匹配则继续提交，不匹配则清理；重复提交同一暂存操作返回原材料。

首个导入切片（“托管导入一份 EPUB”）以更轻的等价机制落地崩溃安全：启动时清空暂存目录并移除无数据库记录的孤儿托管文件，保证不残留半本书或半条记录；显式的 pending/ready 状态机与更完备的恢复协议在“严格查重并恢复中断导入”切片落地。

相同「完整指纹 + 格式」在活跃书库中返回既有材料，在回收站中恢复原材料；相同字节但不同格式、或不同指纹(即使元数据相同)始终创建新材料。编辑 Markdown 时若新内容与其它 ready 材料的导入身份冲突，操作在替换托管文件前失败，不破坏原材料。旧决定“沿用 Readest 抽样 MD5 与 metaHash”在本项目中失效。

恢复只清理 pending 与无主文件；即使 ready 材料的托管副本缺失，也保留材料记录与其批注/覆盖数据，等待显式恢复或永久删除，不在启动阶段静默删除用户材料。

删除先进入应用内回收站并保留全部数据；永久删除才级联移除托管文件和记录。来源元数据不可编辑，用户整理通过覆盖层实现。
