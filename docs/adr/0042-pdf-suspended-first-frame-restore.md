# ADR-0042：PDF 挂起 Runtime 直接恢复当前页首帧

- 状态：已接受
- 日期：2026-08-31
- 关联工单：#61
- 继承决策：ADR-0041、ADR-0040
- 依赖前置工单：#60、#59

## 背景

ADR-0041 已经允许 PDF ReadingView 保留 PDF.js 文档、当前页 Canvas/解码页和
位置快照，但现有 `attach` 在复用文档后仍立即执行异步重排。这样回切时虽然没有
重复打开来源或创建 PDF.js 文档，用户仍可能先看到空白 Canvas、第一页占位或滚动
位置跳动，直到页面重新布局完成。

Issue #61 要求把成功标准提高到“回切首帧直接看到离开前的页面”。这要求把 PDF
页面 DOM、Canvas、文本层、搜索/批注覆盖层和视口状态视为同一个可验证的运行时
快照；快照不满足恢复条件时，必须明确退化到安全重建。

## 决策

### 快照内容与准入

`PdfRenderer` 在 `detach` 完成观察器断开和挂起窗口收缩后，记录以下运行时快照：

- 旧容器的有效宽度、高度和设备像素比；
- 分页/滚动流向、缩放、适配模式、当前页码和滚动位移；
- 当前页已完成的页面节点及其 Canvas、文本层和高亮覆盖层。

分页模式要求当前页的 `PdfPageRenderer` 已完成 Canvas 和文本层构建；滚动模式
还要求当前页状态为 `loaded`，且其页面渲染缓存仍然有效。当前页仍在读取或渲染
时不生成可恢复快照；Runtime 仍可按既有生命周期进入缓存，但回切会走安全重排
路径，避免把半成品快照伪装成可见页面。

### 首帧恢复顺序

当新容器的宽度、高度、DPR、阅读流向、缩放和适配模式均与快照一致时：

1. `attach` 只把原 `pages` 节点和已完成的当前页节点重新挂回新容器；滚动模式
   在接入观察器前写回快照中的 `scrollTop`。
2. 不调用 `setViewport`、`goToPage` 或 `relayout`，因此不会重复取得当前页、
   光栅化 Canvas、重建文本层或改写位置。
3. 接入新的 Resize/Scroll/Intersection 观察器，但不可见 Runtime 的旧观察器、
   输入监听和后台调度保持断开。
4. 当前页首帧挂回后，才通过延迟任务恢复邻页预取和范围读取；邻页失败只影响
   邻页，不能清空或替换已经可交互的当前页。

`BookDocument` 通过一次性的 `consumeRuntimeAttachSnapshot` 能力把这一事实交给
`mountViewDocument`。命中快照且 Workspace 位置相同的挂载不再重复执行位置导航；
没有该能力的 EPUB/Markdown Runtime 继续沿用原有 attach/恢复语义。

### 失效与退化

以下任一条件成立时，快照立即失效并执行安全重排/重建路径：

- 容器尺寸、DPR、流向、缩放或适配模式变化；
- 当前页 Canvas、文本层或滚动页渲染结果不完整；
- 内容版本/缓存键已失配，或 Runtime 已关闭；
- 挂起期间范围读取未能收敛，或 attach 后恢复失败。

改变流向或视口的操作会取消尚未开始的邻页恢复任务。Runtime 关闭仍由
`ReaderRuntime` 所有者统一执行，缓存不直接释放 PDF.js 文档。

## 与 Readest 的继承与取舍

已检查本机 Readest `packages/foliate-js/fixed-layout.js` 的滚动页状态、页面元素
直接挂载和 overlayer 复用路径。AI Reader 继承“页面元素与覆盖层保持在页面状态内、
邻页按最近距离延迟加载”的原则，但没有复制 Readest 应用层代码；本产品仍按
`viewId` 隔离 PDF Runtime，并由 `PdfRenderer` 管理 PDF.js Canvas、文本层和范围
传输预算。

## 验收

`apps/reader/scripts/verify-reader-runtime-cache.mjs` 升级为
`reader-runtime-cache.v5`，在真实 Chrome 的 PDF A→B→A 与 A→B→A→B→A 中验证：

- 当前页 DOM、Canvas、文本层和高亮层节点身份在回切首帧保持不变；
- 首帧具备非空 Canvas、正确页码、正确滚动位置和滚动模式；
- 首帧可交互前不新增 PDF 页面取得或光栅化；
- 邻页恢复在首帧之后运行，既有 PDF.js 文档、来源打开和范围读取不重复创建；
- 原有三 resident、资源预算、双 Editor Group、关闭清理、位置与 LRU 回归继续通过。

单元测试覆盖分页/滚动快照命中、页面节点复用、位置写回、快照不完整和容器尺寸
变化后的回退路径。

## 后果

- 预算内 PDF 回切首帧直接复用离开前的页面结果，用户不会等待当前页重新布局。
- 快照增加了对容器尺寸、DPR 和当前页渲染完整性的严格依赖；无法证明一致时会
  放弃无损首帧并重排，优先保证正确性。
- 邻页预取从恢复首帧中解耦，可能比旧实现稍晚开始，但不会抢占当前页首次交互。
