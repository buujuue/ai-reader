# 使用应用内回收站与显式永久删除

普通删除把阅读材料移入应用内回收站，仅从活跃书库隐藏，保留 `BookId`、托管文件、封面、覆盖以及批注/位置/设置；恢复时继续使用原 `BookId` 与全部阅读数据。只有用户显式二次确认后才永久删除。

## 决策

- `materials` 增加 `deleted_at` 列作为回收站标记：`status='ready' AND deleted_at IS NULL` 为活跃材料，`deleted_at IS NOT NULL` 为回收站材料。`status` 保持 `ready/pending` 不变，避免改动导入状态机。
- 普通删除只写入 `deleted_at` 时间戳，不触碰任何文件或子表；`list_materials` 只返回活跃材料，`list_trashed` 返回回收站材料。
- 恢复即清空 `deleted_at`，材料回到活跃书库，`BookId` 与全部数据保持不变。
- 重新导入时，查重扫描 ready 材料（含回收站）：活跃材料直接去重返回；回收站中相同完整内容指纹则清空 `deleted_at` 恢复原 `BookId`，不新建记录。
- 永久删除只允许作用于回收站材料，按「先删记录（级联清理覆盖/批注/位置/设置）→ 再移除托管文件与封面」的顺序执行；若中途异常终止，启动恢复器会清理无数据库记录的孤儿文件，不会留下错误的 ready 状态。
- 第一版不提供定时或自动清空回收站。

## 理由

删除是破坏性操作，容易误触。回收站让「移出书库」与「释放存储」分离：前者是低风险、可逆转的整理动作，后者是不可逆的清理动作，必须显式二次确认。保留 `deleted_at` 标记而非物理删除，使恢复与同指纹去重复原都无需重建身份，符合规格「稳定 BookId 与可恢复锚点」的长期目标。
