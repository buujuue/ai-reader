# 使用应用内回收站与显式永久删除

普通删除把阅读材料移入应用内回收站，从活跃书库隐藏并移出活跃受管理正文路径，正文副本保留在可恢复私有空间；同时保留 `BookId`、封面、覆盖以及批注/位置/设置。恢复时继续使用原 `BookId` 与全部用户数据，若正文副本确实缺失则明确显示并支持同完整指纹重新关联。只有用户显式二次确认后才永久删除。

## 决策

- `materials` 增加 `deleted_at` 列作为回收站标记：`status='ready' AND deleted_at IS NULL` 为活跃材料，`deleted_at IS NOT NULL` 为回收站材料。`status` 保持 `ready/pending` 不变，避免改动导入状态机。
- 普通删除写入 `deleted_at` 时间戳并把正文从活跃受管理目录移到私有可恢复回收空间，不触碰封面、恢复快照、批注、位置、设置等用户数据；`list_materials` 只返回活跃材料，`list_trashed` 返回回收站材料并标记活跃正文路径不可用。
- 恢复即清空 `deleted_at`，材料回到活跃书库，`BookId` 与全部数据保持不变。
- 重新导入时，查重扫描 ready 材料（含回收站）：活跃材料直接去重返回并在正文缺失时原子恢复；回收站中相同完整内容指纹则恢复原 `BookId`、正文和活跃状态，不新建记录；仅元数据匹配的材料进入显式版本迁移。
- 永久删除只允许作用于回收站材料，先移除该材料的迁移恢复快照，再删除记录（级联清理覆盖/批注/位置/设置），最后移除封面、Markdown 恢复快照、EPUB 派生缓存、活跃正文与可恢复回收正文；快照先行切断，避免后台重试或崩溃窗口静默复活材料。
- 第一版不提供定时或自动清空回收站。

## 理由

删除是破坏性操作，容易误触。回收站让「移出书库」与「清除正文副本」保持可逆：前者通过 `deleted_at` 隐藏入口，正文可由同完整指纹重新关联；批注、进度与设置持续保留。只有用户显式二次确认后才清理全部用户数据和恢复资料，符合规格「稳定 BookId 与可恢复锚点」的长期目标。
