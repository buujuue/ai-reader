# 将 EPUB 批注限制在单一 spine 并使用可恢复软删除

EPUB 文本批注必须落在一个 spine section 内。一个 section 内允许跨页、跨栏和跨段选择；跨 section 的选择直接拒绝保存，不拆分、不拼接、不生成伪造的单一 CFI。这样 CFI、引文和上下文始终描述同一份语义内容。

## 决策

- 选择提交前由 TypeScript 校验 Range 两端所属内容文档及其 spine index；无法证明为单一 section 时不创建批注，并向用户说明需要重新选择。
- 文本锚点保留 CFI、引文、前文、后文与文档版本。原 CFI 未改变时为 `resolved`，引文恢复到新 CFI 时为 `reanchored`，无法唯一恢复时为 `orphaned`（界面显示为“失联”）。
- 一次材料版本恢复涉及多条批注时通过 Repository 的批量保存接口完成一个 SQLite 事务；失败时运行时集合与持久化集合都不切换到半成品。
- 普通批注删除只写入 `deleted_at` tombstone；删除后的记录可列出并通过显式恢复/撤销清除 tombstone，恢复不重算或改变原锚点。只有材料永久清理这种明确的破坏性流程才级联物理删除。
- 第一版批注范围遵循领域上下文，只交付普通高亮、文字笔记和 PDF 区域标记，不引入书签或未来 AI 批注。

## 理由

CFI 的 section 前缀是 EPUB 语义边界。跨 section 拆分会制造多个用户未明确创建的批注，拼接则会把不存在于文档中的范围写入数据；拒绝保存可以保留用户意图并避免静默错位。版本化恢复状态使已重锚和失联都可见，软删除则把普通操作与不可逆清理分开。
