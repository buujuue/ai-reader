# ADR-0026：显式 EPUB 版本迁移与可恢复快照

## 状态

已接受

## 背景

同一 EPUB 的新文件可能保留标题、作者和语言，却改变章节内容与 CFI。完整内容指纹不同意味着它不是精确查重命中，但用户仍可能希望把旧 `BookId` 的阅读进度和批注带到新版本。项目已明确废弃 Readest 的 `metaHash` 自动合并决定，不能因为元数据相似就静默替换材料。

## 决策

1. 导入阶段只把 EPUB、元数据匹配且完整内容指纹不同的文件报告为迁移候选；元数据匹配键是一次性候选信号，不是资料身份、查重键或持久化字段。用户取消时丢弃暂存文件，旧材料和旧数据不变。
2. 候选必须先生成预览。预览逐项展示工作区阅读进度与批注的保持、唯一重锚和孤儿结果；只允许同一 spine section 内的唯一精确引文、且前后文匹配时重锚。零匹配、多匹配、上下文不匹配、跨章节或无法解析的位置都保留为孤儿，不使用最近位置或跨章节猜测。第一版不引入书签迁移。
3. 确认后由 typed `ImportRepository` 调用 Rust 一次性提交：校验旧/新完整指纹与暂存句柄，创建 SQLite 与旧托管 EPUB 一致快照，随后原子替换 EPUB，并在同一 SQLite 事务中更新材料来源、全部批注（含 tombstone）和工作区状态。任何校验、文件替换或事务错误都保持旧材料与旧数据。
4. 快照目录在迁移完成后继续保留，提供显式恢复和清除命令。应用启动时仅回滚 manifest 尚未标记完成的迁移操作；已完成快照不自动清理。恢复会切换数据库与托管 EPUB，并返回旧批注和工作区状态供前端刷新。

## 后果

- 用户能在提交前看到歧义与孤儿批注，避免隐式错误附着。
- `BookId` 保持稳定，但完整内容指纹和来源元数据切换到新 EPUB；EPUB 的 `documentVersion` 继续保持非 Markdown 的 `0`，批注锚点通过内容指纹区分版本。
- 迁移快照占用本地空间，必须提供明确的恢复与永久清除入口；它不进入普通云同步或完整备份归档边界。
- 预览依赖已打开的新 EPUB `BookDocument`，因此迁移语义继续由 Foliate/TS 阅读边界拥有，Rust 只负责持久化和原子完整性。
