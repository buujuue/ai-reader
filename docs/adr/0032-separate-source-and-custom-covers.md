# ADR-0032：来源封面与自定义封面分层托管

## 状态

已接受

## 背景

EPUB 的来源封面和 PDF 首页渲染封面都属于原书派生数据，用户选择的自定义封面属于整理覆盖值。若二者共用一个文件和字段，移除自定义封面会丢失来源封面，重新导入或回收站恢复也无法可靠判断应显示哪一层。

## 决策

1. EPUB 封面选择只由 foliate-js 的 `getCover()` 提供语义；EPUB 2 的 `meta[name=cover]`、EPUB 3 的 `cover-image` 及 Foliate 回退规则不在 Rust 重复实现。
2. PDF 来源封面由 TypeScript 在导入检查阶段通过 PDF.js 直接渲染第一页，不依赖文字层、OCR 或活动 ReadingView；页面、渲染任务和临时 Canvas 在完成、失败或取消后立即释放。EPUB 仍读取 Foliate 封面 Blob。
3. 所有来源封面在 TypeScript 侧限制原始字节与解码像素预算，清洗 SVG，并在需要时保持宽高比缩放到长边 512 像素，使用 JPEG 质量 85 生成位图；封面失败只产生局部降级，不阻断正文导入。
4. Rust 将来源封面写入 `source-covers/<BookId>`，用户自定义封面继续写入 `covers/<BookId>`。`ReadingMaterial` 分别暴露来源封面和自定义覆盖存在性；有效读取顺序为自定义优先、来源兜底。
5. 替换、移除或恢复封面不改变正文完整指纹、文档版本、BookId 或批注锚点。普通删除保留两层封面，永久清理删除两层封面。
6. 完整备份以不同 manifest 条目保存两层封面，恢复时一并切换；来源封面不是材料身份的一部分，也不参与内容查重。

## 后果

- 书库可以在无来源封面时稳定显示占位，在移除自定义封面后恢复原书封面。
- EPUB 的纯 JavaScript 与通过 parity gate 的原生路径共享同一 Foliate 封面语义和缩略图输入；PDF 的导入检查和阅读视图共享同一 PDF.js 页面渲染边界。
- 备份格式需要识别来源封面条目；旧的仅有自定义封面备份仍可通过缺省字段校验。
- 自定义封面当前仍经既有用户选择路径写入托管空间；来源封面派生的 PDF 页面渲染、SVG 清洗与缩放边界不向 Rust 扩散。
