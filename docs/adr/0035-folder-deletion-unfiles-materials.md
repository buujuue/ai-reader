# 删除文件夹时保留材料并转为未归类

删除书库文件夹前必须经过一次明确确认；确认后会递归删除该文件夹及其全部子文件夹，但不删除其中的阅读材料；该子树中的所有材料都转为未归类材料。这样可以避免文件夹整理操作触发材料删除，代价是删除后需要用户重新归类材料，且被删除的子文件夹结构不能恢复。

## 实现约束

- 生产界面通过 `FolderDeleteConfirmDialog` 展示目标文件夹、子树不可恢复的警告，以及材料正文、元数据、批注、阅读位置和打开的 ReadingView 会保留的说明；取消、关闭或 Escape 不执行删除。
- `library.deleteFolder` 是唯一删除入口。`LibraryFolderRepository.deleteFolder` 返回目标及全部后代的稳定 ID；删除成功后 Command 才更新书库 Store，并从 Workspace State 的文件夹展开 ID 中移除已删除子树。
- Tauri Adapter 由 Rust 在一个 `IMMEDIATE` SQLite 事务中先将活跃和回收站材料的 `folder_id` 置为 `NULL`，再以后序顺序删除子文件夹和目标文件夹。任一数据库约束或写入失败都会回滚两部分变更。
- 浏览器降级 Adapter 使用同一公开契约，并在删除文件夹前以一次内存操作清理活跃和回收站材料的归属；失败不会提前更新界面 Store。

## 可验证行为

删除后的活跃材料立即显示在文件夹树下方、回收站上方的未归类区域并继续按有效标题排序；回收站材料仍保留在回收站；主要材料、批注、阅读位置、ReadingView 和其它侧栏状态不受影响。应用级测试覆盖取消、空文件夹、五层子树、材料与回收站材料、失败回滚和重启恢复。
